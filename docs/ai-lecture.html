语料、Agent 与模型：
私有领域中的上下文构造

ABSTRACT

通用语言模型在私有领域中的有效性，取决于当前上下文窗口中是否存在相关、及时、可验证的领域信息。本文把该过程分解为三个对象：语料（可检索的领域证据）、Agent / Harness（上下文构造与工具调度运行时）、模型（对给定窗口的条件生成器）。核心关系是：Agent 通过 Skill、MCP、Spec、工具等机制，从语料与 Prompt 构造上下文，再提交给模型。文中以 Claude Code 与 DeepSeek Harness 的公开架构作为对照，说明同一关系在不同实现中的分层方式与可观测性。

1. 问题与分解

对话式系统按单轮问答工作。Agent 系统按闭环工作：观测环境、构造上下文、调用模型、执行工具、验证结果、再次观测。二者的差别不在生成文本的风格，而在系统能否持续接触外部环境，并在每一步控制模型可见信息的集合。

本文将系统拆为三个对象，而不是按产品功能罗列：

语料 Corpus

领域内可被定位、引用与版本管理的证据集合，包括文本、代码、状态记录与规范。

Agent / Harness

决定读取哪些证据、以何种粒度注入、允许哪些工具、何时停止与如何验证的运行时。

模型 Model

在固定上下文窗口上做条件生成。窗口外的私有事实对该次推理不可及。

变量含义在私有部署中的作用
模型能力规划、推理、生成与工具调用格式遵从提供上限，可替换
上下文质量相关性、时效、信噪比、证据是否可核对决定模型实际可用信息
工具可达范围读文件、检索、查询系统、执行验证的能力使系统接触真实状态
约束清晰度Spec、权限、验收条件限制不可执行或不可审计的动作

2. 概念模型

工作定义 Agent 通过 Skill、MCP、Spec、工具等机制，从语料与 Prompt 构造上下文，并将该上下文提交给模型。模型输出文本或工具调用；工具结果经裁剪后写回上下文或外部存储，进入下一轮。
  1. P1未写入预训练数据、且未进入当前上下文窗口的私有事实，对该次生成不可及。
  2. P2Agent 的主要功能是上下文构造：选择、裁剪、注入与回写，而不是替代模型完成推理。
  3. P3私有领域可积累的资产是语料、规范、Skill、工具协议与权限模型；模型权重是可替换组件。

3. 语料：私有领域的信息基底

预训练使模型获得公共语言与一般程序知识。私有部署中的关键缺口通常不是通用协议本身，而是组织内部的命名、拓扑、现行配置、历史故障约束与流程权限。这些信息若不以语料形式可被检索或读取，就不能稳定进入窗口。

3.1 外延

此处“语料”不限于预训练文本，而指 Agent 可调用的领域证据全集：

显性知识

设计说明、接口约定、故障手册、评审标准、合规条款。问题常在于分散、过期与相互冲突。

结构性记录

源代码、提交历史、工单、配置、监控与日志。现行系统状态多存在于此，而非叙述性文档。

过程约束

排障顺序、发布规则、允许/禁止操作、权限边界。缺少该层时，模型只能生成程序上合理但组织上不可执行的步骤。

负例与边界

已知失败模式与不可复用做法。其作用是缩小生成空间，而不是增加叙述。

3.2 私有领域的信息缺口

通用模型拟合的是公共分布。私有符号、局部拓扑与组织规则落在该分布之外时，模型会用公共模式填补，表现为看似自洽但与现场不符的输出。该现象应首先作为证据缺失处理，而不是单纯的模型能力不足。

参数微调可改变术语偏好与局部格式，但不能替代对“系统当前状态”的读取。相对稳定的做法是：把可变事实放在可检索语料中，把稳定规则放在 Spec 中，由 Agent 按任务注入。

3.3 可用性条件

条件操作定义
可定位人与 Agent 均能按路径、标识符或标题检索到同一对象
可执行含步骤、约束与验收，而非仅含目标陈述

分层摘要短、细节按需加载，避免一次性占满窗口

4. Agent：上下文构造运行时

4.1 定义与循环

定义 模型生成 token。Agent / Harness 决定模型看见什么、可以调用什么、何时停止、如何验证。DeepSeek 的公开表述将二者写作：Agent = Model + Harness。Harness 的作用是使 Agent 能够理解运行环境、使用工具，并在真实环境中持续执行。
步过程
1接收目标与约束（Prompt）
2选择相关 Skill、Spec 与语料片段
3组装系统提示、工具目录与检索结果
4模型输出文本或 tool call
5权限检查后执行工具
6裁剪结果并写回上下文
7验证终止条件；否则继续，或将探索性工作分配给子 Agent

表 4　Agent 循环。Claude Code 与 DeepSeek Harness 均可映射到该过程，差别在分层与实现。

4.2 对照：Claude Code 的分层

据公开资料，Claude Code 可描述为五层。每一层回答一个系统问题，并以不同方式消耗上下文预算：

MCP 连接外部系统（API、数据源、私有工具）。 工具 schema 常驻窗口；连接数增加则基线占用上升
Skills 将可复用步骤编码为按需加载的手册，典型形态为 SKILL.md。 仅在相关任务注入，占用较低
Agent 主会话：读取、修改、调用工具，并对用户目标负责。 对话、文件读取与工具输出在主窗口累积
Subagents 在隔离上下文中执行探索，只将结论返回主会话。 用独立窗口换取主上下文的信噪比
Agent Teams 跨会话协作；成员各持独立上下文，通过消息汇总。 适用于并行与长程分工

图 2（表列）　Claude Code 五层及其上下文代价。

与上下文构造直接相关的机制：

  • Skill：可检索的操作程序，不把全部流程永久写入系统提示。
  • Spec：如 CLAUDE.md 或仓库内单一事实来源文档，承载稳定规则，应短且可版本管理。
  • 工具：使模型接触仓库与运行环境；返回值必须切片或摘要，否则占用窗口。
  • 上下文管理：窗口为硬约束。接近上限时采用压缩、清场或子 Agent 隔离。

扩展机制的上下文成本大致为：Hooks（接近零）→ Skills（低）→ Plugins（中）→ MCP（高，因 schema 常驻）。该顺序用于选择“把能力做成常驻连接还是按需手册”。

4.3 对照：DeepSeek Harness

DeepSeek Harness 的公开设计可归纳为两条原则。

Everything is a plugin

模型、工具、Skill、会话、沙箱、存储、循环、调度与 UI 均以插件提供，可通过配置替换或重组，而不修改核心源码。

Every run is traceable

模型可见内容写入只追加的 session log：系统提示、推理、工具调用与结果、子 Agent 调度、每一次上下文注入。恢复、分叉、检索与回放共用同一事件流。

可观测性的操作含义是：失效分析应首先检查该轮窗口中的实际注入，而不是只比较最终文本。Trajectory 按来源检查记录，使上下文构造成为可审计对象。

模式配置意图
Standard完整工具集：文件、shell、搜索、Skill、规划、子 Agent、工作流
Code能力与 Standard 相当；以生成代码编排多轮工具调用
Minimal保留 shell 与编辑器，用于在最小 harness 下评测模型
Creator检查运行时、试验插件并组合新模式

5. 模型：窗口上的条件生成器

在本框架中，模型是对上下文窗口 C 的条件分布 p(y | C)。提高模型能力改变的是在既定 C 上的推理上限；改善语料与 Agent 改变的是 C 的内容。二者不可互相替代。

给定窗口内可完成窗口外不可假设已完成
基于已注入证据做规划、编码、摘要与格式化工具调用 未检索到的私有标识、未读取的现行配置、未写入 Spec 的禁令
在证据充分时提出可验证假设 在无工具反馈时断言外部环境的当前状态
在噪音较低时保持目标一致性 在超长、未裁剪的工具输出中稳定抽取关键约束

表 8　模型能力的边界由窗口内容界定。

因此，私有系统评测若只比较模型榜单，会混淆两类误差：模型在给定证据上推理失败，以及证据从未进入窗口。Minimal harness 的作用是把第二类因素降到最低，从而观察第一类。

6. 推论：私有部署的变量顺序

由 P1–P3 可得一个可操作顺序。该顺序是工程依赖，不是演示话术：

序对象完成标准
1语料规范、接口、故障记录与权限边界可被检索；冲突与过期可被识别
2Spec / Skill稳定规则进入 Spec；按任务加载的程序进入 Skill，而不依赖每次对话重述
3工具 / MCP系统能够读取代码、查询状态并运行验证；仅在检索与读文件不足时增加常驻 MCP
4模型与运行时选择可替换的模型，以及 Claude Code 类产品或 DeepSeek Harness 类可重组运行时
5轨迹审查失效时检查该轮注入了什么；优先修正语料、Skill 与检索，而不是首先替换模型
