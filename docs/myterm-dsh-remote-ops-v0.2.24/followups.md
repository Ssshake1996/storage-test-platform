# remote_terminal_send 后续优化方案

v0.2.24 把三类设备 CLI 交互收进同一次 `remote_terminal_send`：末尾 `(y/n)` 自动回答、最后一行 `--More--` 自动退出、参数错误画面自动 SIGINT。下面是还没做、但值得做的改动。按对模型往返和误操作的影响排序。

## P0：让模型少打一轮，同时避免重复执行

1. **等到提示符再返回。** 现在静默 `quietMs`（默认 700ms）就返回，慢设备的 `(y/n)` 或 `admin:/>` 还没出现，模型仍要再读一次。增加 `promptPattern`，在超时内继续等到末尾匹配该提示。匹配到交互提示符时可以把 `completion` 从 `unknown` 收窄为 `prompt`，仍然不伪造退出码。
2. **`requestId` 去重。** 快捷命令已经有 10 分钟回执去重，`remote_terminal_send` 没有。自动确认成功后，模型若重试同一次 delete/create，会再执行一遍。沿用 quick dispatch 的 `requestId` + owner + 命令指纹，重复请求直接返回上一次回执。
3. **`confirmText`。** 应答目前固定 `y\n`。有的 CLI 只把 `\r` 当提交。默认保持 `y\n`，调用方传 `confirmText: "y\r"` 即可，不必再改插件。

## P1：缩小误清行和误回答

4. **参数错误清行改为可关闭，并收紧触发条件。** v0.2.24 对每次 send 都扫描。后续默认仍开启，但增加 `autoClearParameterError: false`。只在最后约 30 行命中，并且最后一行不像普通提示符时才发 SIGINT。清行后若恢复输出里仍拼着上一条命令，再发一次，最多两次。能判断当前没有前台进程时，优先发擦行（Ctrl+U）而不是 SIGINT，避免误杀正在跑的命令。
5. **批量工具透传。** `remote_terminal_batch` 仍是普通 `send`。把 `autoConfirm`、`confirmPattern`、`autoQuitMore` 传到每个目标，否则多设备任务又退回一轮一确认。
6. **设备档案。** 为存储 CLI 增加可选 profile（例如确认文案、分页符、提示符、是否默认自动确认）。模型只选档案，不必每次记三个参数。档案不能默认对所有 SSH 环境打开自动确认。
7. **分页符放宽。** 现在只认最后一行里的 `--More--`。后续用可配置 `pagerPattern` 覆盖 `---- More ----`、`<--- More --->`、`(Press ENTER)`，退出字符默认仍是 `q`。

## P2：上下文和可观察性

8. **压缩已回答的警告。** 双重确认的 WARNING 往往很长。增加 `compactPrompts`，把已经自动回答的提示换成一行摘要，原始输出仍留在终端缓冲里，工具结果只带摘要和 `autoConfirmed`。
9. **界面能看见插件代操作。** 标记不进滚动缓冲是故意的，否则续读会把元数据当成设备输出。Sidebar 事件条应显示“已自动回答 N 次 / 已清行 / 已退出分页”，方便人和模型核对。
10. **接管会话不要中断自动化。** 宿主接管的 SSH 会话每次 `refresh` 会换新的输出流。v0.2.24 遇到流被替换就停止自动回答。应在新快照的末尾继续判断，而不是直接放弃。
11. **真机回放。** 单元测试使用了确认文案、`--More--` 行和 `^` / `[host_group_id=?]` 样例，但是假终端。下一步用一份脱敏的 PTY 字节记录回放，覆盖 GB18030 和行尾 `\r\n`，再在有 DSH profile 的机器上做 3080 验收。不要把假终端通过写成真机通过。

## 不建议做

- 不要把 `autoConfirm` 默认改成 true。它会在用户没要求的高风险命令上自动回答 yes。
- 不要在插件里再做一套 Agent 循环、权限门禁或长期记忆。这些仍属于 DeepSeek Harness。
- 不要为了清行去解析所有交互程序的退出码。`completion: "unknown"` 继续表示“静默不是完成”。
